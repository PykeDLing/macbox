# 可以写入的文件夹

## 问题

本机隔离的盒子里，应用只能写盒子自己的主目录、临时目录、App 目录，开了「共享下载」时还能写你真实的「下载」
（`SandboxProfile` 的 `(deny file-write*)` 和 `downloadsRule`）。夸克网盘把下载位置改到别的文件夹时，会先在里面建
`test-<uuid>.txt` 试写，被挡后就提示没有权限；运行报告里记着「写入你的个人文件夹 ~/game/test-….txt」。外接硬盘
`/Volumes/…` 同样写不了。

应用自己的「选择文件夹」对话框扩展不了 sandbox-exec 的规则：规则在启动时就定了，运行中加不了。所以要由你在
MacBox 里选好文件夹，**重新打开应用后**才生效。

## 数据：box.json

```swift
/// 应用可以写入的盒子外的文件夹（真实路径，按添加的先后）。没有时不写这个字段（nil），box.json 和旧版一样
var writableFolders: [String]?
```

- 存的是**选的时候**用 `FileOps.realPath` 解析出的真实路径：经由符号链接选的存成链接指向的地方。
- **之后不再解析**。生成规则时原样使用存下的路径，不碰文件系统：
  - 应用把选定的文件夹删掉、换成指向别处的链接（它在 subpath 里，做得到）时，沙盒按解析后的真实路径判断，
    写进链接的内容落在别处、被挡住（已用 sandbox-exec 验证）。要是 MacBox 每次启动重新解析，就会顺着链接把别处放行。
  - 文件夹被删掉：规则照常生成，应用照常打开；应用自己重新建这个文件夹也可以（subpath 包括它自己）。
  - 外接硬盘没插上：同样照常打开。`/Volumes` 只有 root 能写，应用建不出同名的挂载点。
  - MacBox 不去读这些文件夹（「文稿」「桌面」、外接硬盘要授权，读了会弹窗）。
- 旧版 MacBox 不认识这个字段，读的时候忽略；在旧版里改了设置再存，这个字段会丢掉（和「允许联网」一样）。

## 规则：SandboxProfile

紧跟 `downloadsRule`，每个文件夹一条，照它的写法带 `(with report)`：

```
(allow file-write* (subpath "/Users/x/game") (with report))
```

放在盒子自己的 `(deny file-write* (subpath boxRoot))` 和骨架规则之前：即使有一条和盒子重叠，盒子的规则在后面，仍然以盒子的为准。

生成规则时对存下的路径再做一遍不碰文件系统的检查（见下面「哪些不能选」，除了要读磁盘信息的那条），
不合格的跳过：box.json 应用改不了，只防手工改过的、以后版本收紧了的。

## 哪些不能选

选的时候检查，不合格的不加，告诉你原因：

| 不能选 | 原因（界面上的说法） |
| --- | --- |
| 整块磁盘的根：`/`、`/Volumes/<名字>`，以及其他挂载点（选的时候读卷信息判断） | 范围太大，请在里面选一个文件夹 |
| 主目录本身和它的上级（`/Users`） | 范围太大，请选一个子文件夹 |
| `~/Library` 及其下 | 那里是各个 App 的数据和设置 |
| `~/Applications` 及其下 | 聚焦里的启动器在那里，改了它们就能在盒子外运行 |
| 路径里有隐藏文件夹（以 `.` 开头的一段：`~/.config`、`~/.ssh`……） | 放的多是配置和凭证，写进去的配置会被你自己的终端、工具执行 |
| MacBox 的数据目录，它的上级和下级 | 盒子里的本来就能写；MacBox 自己的记录不能让应用改 |
| 系统目录：`/System` `/Library` `/Applications` `/usr` `/bin` `/sbin` `/private` `/etc` `/var` `/tmp` `/opt` `/cores` `/dev` 及其下 | 系统和你装的 App 在那里 |
| `~/Downloads` 本身 | 请用上面的「共享「下载」文件夹」；里面的子文件夹可以选 |

「文稿」「桌面」本身可以选（是你的选择），对话框里提示最好选一个专门的文件夹。
同一个文件夹选两次只留一个；文件夹在另一个已选的里面时照样加上（规则重叠无害）。

## 界面：详情里的「文件」

放在「共享「下载」文件夹」开关下面：

```
可以写入的文件夹
  📁 game                         ~/game                      ⊖
  💽 下载   「Backup」没有接上       /Volumes/Backup/下载          ⊖
  [添加文件夹…]
  应用只能在盒子里和这些文件夹里写文件。在应用里把下载位置改到别处之前，先把那个文件夹加到这里，
  重新打开应用后生效。应用可以新建、修改、删除里面的文件；删除应用、清除数据、还原都不会动它们。
```

- 「添加文件夹…」打开 MacBox 自己的选择框：只能选文件夹，可以新建文件夹，可以多选；按钮是「允许写入」，
  说明是「选择「夸克网盘」可以写入的文件夹」。
- 每一行：名字、路径（主目录写成 `~`）、移除按钮；右键「在访达中显示」（由访达打开，MacBox 不读）。
- 外接硬盘上的文件夹：用系统已挂载的卷列表（不碰那块盘）判断有没有接上，没接上的在行里注明。
  本机文件夹不检查在不在（检查要读「文稿」这类受保护的位置）。
- **应用运行时也能改**：这正是要用的时候（在应用里改下载位置被拒，回到 MacBox 加上）。说明改成
  「重新打开「夸克网盘」后生效」。其他开关运行时不能改，这一项例外。
- 有外接硬盘、网络磁盘上的文件夹时多一段说明：
  > 应用第一次写外接硬盘（或网络磁盘）时，macOS 会问是否允许「夸克网盘」访问可移除的宗卷。这是在问盒子里的这个应用，
  > 点「允许」它才能写入。macOS 会记住这个选择，删除应用后也还在，可以在「系统设置 › 隐私与安全性 › 文件与文件夹」里撤销。
- 有「文稿」「桌面」里的文件夹时同样说明（问的是访问「文稿」/「桌面」文件夹）。
- 删除应用的确认里，「它存进你「下载」文件夹的文件不在盒子里，会保留」扩展到这些文件夹。

### 从拦截记录直接允许

实际的流程是：在应用里选了文件夹 → 应用说没有权限 → 回到 MacBox。这时详情里的拦截记录正好列着
「写入你的个人文件夹 ~/game/test-….txt」。在这类记录旁边放一个「允许写入「game」…」按钮（取被挡文件所在的文件夹，
不合格的不显示按钮）。拦截记录收起时也列出「写入「game」被挡住了 · 允许写入…」，不用先展开。点了先确认：

> 允许「夸克网盘」写入「game」？
> 它可以新建、修改、删除「~/game」里的文件，删除应用后这些文件仍然保留。重新打开「夸克网盘」后生效。
> [允许写入] [取消]

这样不用自己在选择框里找到那个文件夹。路径来自系统日志，应用可能故意去写一个大的文件夹来引你点，
所以照样经过上面的检查，并且必须确认。

## 运行报告

- 写入照「下载」的办法记：带 report 的规则让系统日志每次写入都记一笔（`ViolationMonitor` 已经把放行的
  `file-write*` 交出来），`DownloadWrites` 推广成按多个位置汇总（「下载」和每个可以写入的文件夹，路径最长的那个优先），
  新建又删掉的（夸克试写的 `test-….txt`）照旧不算。
- 文件位置新加一类 `FileArea.Location.folder`，路径写成 `~/game/电影.mp4`、`/Volumes/Backup/下载/电影.mp4`，按文件夹里的顶层项目汇总。
  旧版 MacBox 读到这一类会读不出那一份报告（只在退回旧版时）；这一版起读位置时认不出的不让整份报告读不出。
- `RunReport` 新加可选字段 `writableFolders: [String]?`：这次运行时可以写入的文件夹（写成应用眼里的样子）。
  报告页顶部的标签、导出的 Markdown 里列出来；「实际都在 MacBox 的盒子里（「下载」除外）」改成「（「下载」和可以写入的文件夹除外）」。
- 看不到大小、会因为日志限流漏记，和「下载」一样，说明里已经写了。

## 不做的

- 运行中加文件夹立即生效：sandbox-exec 的规则启动后改不了；沙盒扩展（`sandbox_extension_consume`）要应用自己调用。
- 跟着文件夹移动、改名（书签）：移动后按新位置放行就是 MacBox 自己在扩大范围，不如让你重新选。
- 区分同名的外接硬盘：换一块同名的盘插上，同一个路径照样能写。那是你选过的路径，不另外记卷的标识。
- `~/Library/CloudStorage`（Dropbox、OneDrive 等）、iCloud 云盘：在 `~/Library` 下，这一版不能选。
- 虚拟 Mac：不适用（文件夹由虚拟 Mac 的共享文件夹负责），只在本机隔离时显示。

## 测试

- 单元测试（`swift test --no-parallel`，`MACBOX_DATA_ROOT=/tmp/mbx.XXXX`）：
  - 检查：每一类不能选的都被拒绝、原因对；正常的子文件夹、外接硬盘上的文件夹通过；经由链接选的存成链接指向的地方。
  - 规则：sandbox-exec 实测能写选定的文件夹、写不了旁边的；选定文件夹被换成链接后写不进链接指向的地方；
    文件夹不存在时照常启动；没有选时 box.json 不写这个字段，旧文件照常读。
  - 报告：多个位置的写入汇总、最长路径优先、试写的临时文件不算；带 report 的写入真的出现在系统日志里、算进报告。
- 测试实例：用一个照夸克做法写的小测试 App（改下载位置时先试写 `test-<uuid>.txt`，再下载一个小文件进去）：
  没加时被挡、拦截记录和夸克的一样；加上后重新打开，试写通过、下载成功，运行报告列出写入；文件夹删掉、硬盘没插上时照常打开。
- 界面（computer-use）：添加文件夹、拒绝太宽的、移除；拦截记录旁的按钮；外接硬盘没接上的提示。
