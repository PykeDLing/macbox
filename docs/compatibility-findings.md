# 兼容性实测中发现的问题

2026-11-11、12 实测国产软件（见[兼容清单](compatibility.md)）时发现的 MacBox 自己的问题，按对用户的影响排序。标了“已修”的在 0.4.5 里。

1. **迅雷的下载服务被守卫结束。** 迅雷把下载放在 App 包里的 XPC 服务里，这类服务由系统直接启动、不在沙盒里，守卫会结束它。结果是界面正常但下载用不了：新建一个下载任务，迅雷报“下载引擎出现异常”。试过让这个服务进沙盒（在 App 包里给它加一个先套沙盒再启动它的替身）：macOS 发现 App 包被改动，直接判定“迅雷已损坏，无法打开”，这条路走不通。**已改**：这类被结束的服务在运行报告里单独记成「启动自带的后台服务」，退出应用后 MacBox 说明是哪个服务用不了，并建议改用虚拟 Mac，不再是界面正常、功能悄悄失效。
2. **向日葵起不来，而且事先没有提示。** 静态检查只报了“安装脚本已跳过”。运行时它写真实主目录被拦下后卡住：没有窗口、不响应退出。这种“按真实主目录路径写 Application Support 被拦”的情况，现在不会触发改用虚拟 Mac 的建议。
3. **“需要管理员权限的辅助程序”判得偏重（部分已改）。** Chrome、Edge、Motrix、迅雷都因为包里带一个辅助程序被提示“可能需要虚拟 Mac”，而 Motrix 和迅雷实测可以在本机隔离里启动，Chrome、Edge 的辅助程序只管自动更新。0.4.5 起，辅助程序名字里都带 update 的（Chrome、Edge）只记成功能受限，添加时不再提示；别的照旧。
4. **剪映的在线安装器接手失败（已修）。** 三个原因叠在一起：它下载的磁盘映像存成了 `.zip`，MacBox 按扩展名当压缩包去解；MacBox 请它退出时它先问“确定取消下载吗”，不走，一取消就把下载的东西删掉；上一次运行下好的安装包，这次运行不认。现在安装包按内容认格式，安装器去挂载它的那一刻先克隆一份保住，再请安装器退出（几秒不走就直接结束），以前下好的也接手。
5. **问盒子里的文件夹“可不可写”，答的是不可写（已修）。** 为了不让主目录、临时目录这些文件夹被删除或换成链接，沙盒规则挡住了对文件夹本身的所有写操作，连“这个文件夹可写吗”的询问也答了“不可写”，尽管往里面新建文件没有问题。剪映启动时这样检查临时目录，查不过就弹“temp 目录无写入权限”。这样检查的应用不止剪映（Qt 的 `isWritable`、`isWritableFileAtPath`）。现在只放行这一种询问，文件夹本身照样不能删除、改名、改权限。
6. **飞书第一次打开会自己退出。** 第二次正常。像是它首次运行时的自重启没有接上。
7. **有东西落在盒子外。** 这次测试结束后，盒子外多出：`~/Library/Group Containers/group.com.baidu.BaiduNetdisk-Mac`（百度网盘）、`~/Library/Preferences/com.tencent.tds.bugly.plist`（腾讯视频）、`~/Library/Preferences/org.chromium.Chromium.plist`（飞书）、`/private/tmp` 下的 `boost_interprocess`（百度网盘）和 `com.sogou.inputmethod`（搜狗安装器），以及 MacBox 挂载 dmg 时系统写的 `~/Library/Logs/fsck_hfs.log`。两个偏好设置运行报告都列出来了；Group Containers 那个目录和 `/private/tmp` 里的没有提示。Group Containers 里的目录受系统保护，命令行删不掉，要在访达里手动删。
8. **盒子里的应用能找到本机正在运行的其他应用。** 腾讯微云在盒子里显示出了本机微信账号的头像和昵称，并提供快捷登录。应该是通过本机端口联系上的（没有进一步确认）；本机隔离不挡本机回环地址，README 的限制里没有写到这一点。
9. **有的应用名字显示成英文。** 企业微信显示成 “WeCom”：它没有简体中文的 InfoPlist 本地化，MacBox 退到了英文那份，而不是 Info.plist 里本来的“企业微信”。迅雷显示成 “Thunder” 是它自己包里就这么写的。
10. **主程序退出后后台服务还留着。** 百度网盘退出后 `netdisk_service` 继续运行，盒子一直显示“运行中”。这是它本来的行为，但用户可能不知道要再点一次「退出」。
11. **有的应用运行过之后，MacBox 锁不回去（未解决）。** 迅雷、剪映运行过一次之后，MacBox 在它们退出时去掉执行权限的操作被系统拒绝（系统日志里是 `System Policy: MacBox deny file-write-mode`），App 一直留着执行权限，「App 平时上锁」对它们就失效了，界面上也没有任何提示。用正式安装的 MacBox 0.4.4 新添加一份迅雷、运行一次再退出，结果一样，所以不是测试副本的问题。作者日常用的两个盒子（夸克网盘、网易有道翻译）最近运行后是锁着的，哪些应用会这样、为什么，还没有查清；看起来是 macOS 对“修改别的 App 的包”的限制（App 管理）。 0.4.5 起，锁不上的应用在详情面板里会列出「退出后没能锁上」，至少看得见。
12. **守卫会误杀一种命令（已修）。** `python3 - 盒子里的路径` 这样从标准输入读脚本、把盒子里的路径当参数的命令，被当成“在沙盒外运行盒子里的脚本”结束了。现在单独一个 `-` 按“脚本来自标准输入”处理。
